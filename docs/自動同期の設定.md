# 開発本体への自動同期 ― 設定手順（1回だけ）

公開デモ（このリポジトリ）の `index.html` と `docs/` を、開発本体
**NEXCAREjapan/nexcare-kintai** へ自動で送るための設定です。

設定が終わると、デモを直して push するたびに、開発本体に
**「公開デモの変更を取り込む」というプルリク（取り込み依頼）が自動で立ちます。**
中身を確認してマージするだけで、開発本体が最新になります。

> 設定しないうちは何も起きません（同期はスキップされ、エラーにもなりません）。

---

## 手順1: アクセス用のトークンを作る

GitHub の <https://github.com/settings/personal-access-tokens/new> を開いて、次のように作ります。

| 項目 | 入れる値 |
|---|---|
| Token name | `nexcare-kintai-demo 同期用` |
| Resource owner | **NEXCAREjapan** を選ぶ（自分のアカウントではない） |
| Expiration | 1年（期限が切れたら作り直し） |
| Repository access | **Only select repositories** → `nexcare-kintai` を選ぶ |

**Permissions**（権限）は次の2つを「Read and write」にします。

- **Contents** … Read and write
- **Pull requests** … Read and write

「Generate token」を押すと `github_pat_...` という文字列が1回だけ表示されます。
**この画面を閉じると二度と見られません。** コピーして次の手順へ進んでください。

> Resource owner に NEXCAREjapan を選ぶと、組織の管理者の承認待ちになることがあります。
> その場合は承認されるまで同期は動きません。

## 手順2: このリポジトリにトークンを登録する

<https://github.com/tsujiryota-cpu/nexcare-kintai-demo/settings/secrets/actions> を開いて、
**「New repository secret」** を押します。

| 項目 | 入れる値 |
|---|---|
| Name | `MIRROR_TOKEN` （この名前でないと動きません） |
| Secret | 手順1でコピーしたトークン |

「Add secret」を押して完了です。登録したトークンは以後表示されません（画面上も伏せ字になります）。

## 手順3: 動くか試す

<https://github.com/tsujiryota-cpu/nexcare-kintai-demo/actions/workflows/sync-to-main-repo.yml>
を開いて、右上の **「Run workflow」** を押します。

緑のチェックが付いたら成功です。開発本体の
<https://github.com/NEXCAREjapan/nexcare-kintai/pulls> にプルリクが立っています。

赤いバツが付いたときは、そのログを開いて Claude に見せてください。よくある原因は
「トークンの権限が足りない」「組織の承認がまだ」「Resource owner を間違えた」の3つです。

## 同期されるもの・されないもの

| 保存先 | どうなるか |
|---|---|
| 公開デモ URL（GitHub Pages） | main に push した時点で自動反映（この設定とは無関係） |
| **開発本体 NEXCAREjapan/nexcare-kintai** | **この設定で自動。プルリクをマージすれば反映** |
| Claude Artifact | クラウドセッションから更新できる（辻さんの許可があれば毎回反映） |
| OneDrive | **自動化できない。** 辻さんのPCセッションで反映 |
| Googleドライブ | **自動化できない。** 辻さんのPCセッションで反映 |

OneDrive と Googleドライブは、いまのところ手動です。区切りのいいところで、
PCセッションで「クラウドの変更を同期して」と伝えてください。

## 送るファイルを変えたいとき

`.github/workflows/sync-to-main-repo.yml` の中の、コピーしている場所を書き換えます。

```yaml
cp ../index.html index.html
mkdir -p docs
cp -a ../docs/. docs/
```

開発本体のファイル配置がデモと違う場合も、ここのコピー先を直せば合わせられます。
`CLAUDE.md` はデモ専用の作業ルールなので、あえて送っていません。

## プルリクを経由せず、開発本体に直接反映したいとき

同じファイルの末尾を、プルリクを作らずに開発本体の既定ブランチへ push する形に
書き換えれば直接反映にできますが、**取り込む前に中身を確認できなくなります。**
まずはプルリク方式で運用して、慣れてから切り替えることをおすすめします。
